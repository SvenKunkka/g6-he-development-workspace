# 三轮审计回归记录

日期：2026-07-23

范围说明：这三轮只覆盖签名镜像的静态审计、产品契约比对和审计工具本身。
因为源码、签名策略和恢复路径缺失，未修改固件逻辑，也未进行烧录测试。

## 第 1 轮：建立缺陷检测基线

- 结果：7/8 测试通过，1 项失败。
- 失败：`B-03`（空配对键）和 `B-04`（RF/bond 日志）未被报告。
- 根因：固件字符串提取器只保留通用关键字，遗漏 `ppt`、`bond` 和
  `access code`。
- 修复：扩充关键字表；保留二进制原始偏移作为证据。

## 第 2 轮：验证漏检修复

- 结果：8/8 测试通过；11/11 镜像身份、布局、内部 SHA-512 和向量表检查通过。
- 复核发现：USB 序列号检测使用全文字符串匹配，可能被同一快照中的其他设备误触发。
- 修复：按 G6 HE 的精确 VID/PID `3434:D086` 解析 `usb_devices`，再判断
  `serial` 是否为空；增加目标设备证据断言和缺陷 ID 唯一性测试。

## 第 3 轮：验证精确设备匹配与最终输出

- 结果：10/10 单元测试通过；11/11 发布审计检查通过；缺陷 ID 全部唯一。
- 原始鼠标 SHA-256：
  `b77f21d0d28fc9315f4b667e2e24046b49ad9e480749a21a9888e989cfe85ce0`
- 原始接收器 SHA-256：
  `c3b27594a7f636ef0324d61a61a018511209ff2de59104e1e1bb6eaa6021a1cf`
- 两个值都与基线一致，确认测试没有修改用户原始固件。

## 当前真机观察

- 第三轮后仍枚举到 G6 HE：`3434:D086`、USB 480 Mbps、4 个 HID 接口、无序列号。
- Mouse 接口 `ReportAvailableCalls/ReportAvailableRuns` 当前为
  `14434/14434`，间隔 2 秒静止采样未变化。
- 静止不产生相对鼠标报告本身可能是正常行为，因此该结果不能单独证明卡死或恢复。
  需要在用户持续移动/点击的同步窗口采样，或取得固件 fault/coredump。

## 结论

三轮循环已经修复并验证两处分析链路问题，但不能算作“固件 Bug 已修复三轮”。
固件三轮修复测试必须在取得可构建源码、签名/开发 key 策略和恢复手段后重新执行。
