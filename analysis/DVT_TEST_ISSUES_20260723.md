## P0：阻断使用或产生危险输入

### T-03 [critical] 2.4G 切换 DPI/回报率时所有按键和滚轮被触发

- 原始现象：2.4G 下切换 DPI 和回报率时，所有按键及滚轮都会被触发。
- 影响：可能在游戏、桌面或生产软件中产生不可预测操作。
- 可能根因：
  - 切档时复用了未初始化或未清零的 HID report；
  - 模式切换清队列时把状态位当作边沿事件发送；
  - RF profile 更新与按键/滚轮采样并发，形成撕裂报告。
- 修改方案：
  - 切档事务开始前发送 neutral report；
  - 暂停事件发布，原子更新配置并清空按键、滚轮和 pending report；
  - 重新采样稳定状态后再开放事件；
  - 所有 HID report 使用显式零初始化，不复用脏缓冲区。
- 验收：2.4G 下分别切换每个 DPI/回报率档 1,000 次；除目标设置变化外，
  按键、滚轮和移动事件计数必须为 0。

### T-04 [critical] 光微动在 2K/4K/8K 下左右键无功能

- 原始现象：光微动模式下，回报率 2000/4000/8000 Hz 时左右键无功能。
- 影响：高回报率配置下主按键完全不可用。
- 可能根因：
  - 光微动扫描或 ADC/比较器处理任务被高频 USB/RF 发送任务饿死；
  - 高回报率 profile 错误关闭光微动中断或选择了磁微动输入源；
  - 光微动事件队列容量/节流逻辑只按 1K 设计。
- 修改方案：
  - 将微动扫描与 HID 发送解耦，使用独立定时器/中断和带时间戳事件队列；
  - profile 切换后显式校验 optical input source、IRQ 和 debounce 状态；
  - 增加队列溢出计数与自动恢复，不允许静默丢弃主键事件。
- 验收：光微动在 125–8000 Hz 每档执行左右键各 10,000 次，零永久失效，
  丢键率、重复率和延迟满足批准规格。

### T-08 [critical] 2.4G 接收器拔插回连后产生幽灵按键和滚轮

- 原始现象：2.4G 模式拔插接收器并回连成功后，使用鼠标时按键和滚轮自动触发。
- 影响：连接恢复后产生非用户输入。
- 可能根因：断链期间缓存的边沿事件在回连后重放；首次同步包没有强制 neutral
  状态；接收器与鼠标的 report sequence 没有在新会话复位。
- 修改方案：断链时丢弃非持久输入队列；新 RF session 生成新 epoch/sequence；
  回连的首个有效报告必须是 neutral snapshot，之后只发送新采样事件。
- 验收：拔插接收器并回连 500 次，回连前后不操作期间的按键、滚轮事件必须为 0。

### T-09 [critical] 切到 2.4G 时产生幽灵输入且左键保持按下

- 原始现象：拨动开关到 2.4G，按键和滚轮自动触发；左键一直按下，直到移动鼠标
  或再次按键才被释放。
- 影响：可能造成拖拽、连续射击或不可逆界面操作。
- 可能根因：进入 2.4G 时 previous/current button bitmap 未同步；发送了 press
  snapshot 但 release report 依赖下一次运动/输入事件。
- 修改方案：
  - 模式入口将 previous/current 状态同时初始化为稳定 GPIO/光磁采样值；
  - 无论是否有移动，都立即发送 neutral/release 同步包；
  - release report 不得依赖 motion path；
  - 增加“按下状态最长保持时间”诊断保护，但不能用超时掩盖根因。
- 验收：从有线/BLE/关闭状态切入 2.4G 各 1,000 次；不得产生幽灵事件，
  host 端不得保留任一按键按下状态。

### T-12 [critical] BLE 回连失败休眠后无法通过按键或移动唤醒

- 原始现象：蓝牙回连失败进入休眠后，按键和移动鼠标均无法唤醒。
- 影响：设备只能通过拨动开关、重新上电等方式恢复。
- 可能根因：失败路径进入了错误的 system-off 状态；GPIO、光微动、磁微动或
  PAW motion 中断未配置为 wake source；休眠前中断被关闭后未重新挂载。
- 修改方案：统一 BLE reconnect-failed 与正常休眠的电源入口；在睡眠提交前验证
  至少一个按键和 motion wake source 已 arm；唤醒后重建传感器与 BLE 状态机。
- 验收：制造回连失败 200 次；每次休眠后按键和移动均能唤醒并重新开始回连。

### T-17 [critical] 2.4G 使用中回报率突降至约 24 Hz

- 原始现象：2.4G 使用过程中光标突然变慢，回报率只有 24 Hz。
- 影响：运行中严重降速，基本不可正常使用。
- 可能根因：RF 重试/拥塞错误地触发低功耗调度；高频定时器丢失后退化到约
  40 ms 周期；传感器或 report queue 卡在慢速恢复路径。
- 修改方案：对 sensor sample、report enqueue、RF transmit、ACK/retry 分别记录
  heartbeat；检测速率异常后局部重启对应模块；RF 重试不得改变用户配置档位；
  保存降频原因和状态转移。
- 验收：2.4G 各回报率进行 24 小时运动与干扰压力测试，不得无指令降档；
  故障注入后 2 秒内恢复且留下可定位原因。

### T-18 [critical] 电池电压 3.5 V 或更低时高概率无法开机

- 原始现象：电量 3.5 V 或低于 3.5 V 时，高概率无法开机。
- 影响：可用电量范围缩短并出现随机启动失败。
- 可能根因：欠压阈值/迟滞配置错误；启动浪涌造成 brownout；电池 ADC 换算或
  高压电池曲线不匹配；DC/DC、传感器和 RF 同时启动导致压降。
- 修改方案：分阶段启动电源域；校准 ADC 与 UVLO 阈值；记录 reset reason 和
  启动最低电压；在电源稳定后再启动 PAW/RF/高回报率时钟。
- 验收：在批准的最低工作电压至满电范围内做电压阶梯和 100 次冷启动，
  启动成功率及 brownout 行为符合电源规格。

### T-19 [critical] 无电池时仅插 USB 高概率无法开机

- 原始现象：不接电池，仅插入 USB 线时高概率无法开机。
- 影响：有线供电路径不能作为可靠的启动或恢复通道。
- 可能根因：battery-absent 被误判为欠压故障；VBUS、电池和充电 IC 的电源仲裁
  错误；启动流程在检测到电池 ADC 无效后提前退出。
- 修改方案：实现明确的 `battery-absent + VBUS-present` 启动路径；不得把缺失的
  电池 ADC 样本当作不可启动；验证 power mux、充电 IC、DC/DC 和负载启动顺序。
- 验收：无电池条件下 USB 冷插、热插和软件/硬件复位各 100 次，均能稳定启动并
  完成有线输入、配置和 DFU 枚举。

## P1：高严重度功能/性能问题

### T-02 [high] 有线组合键切档时侧键本身也被触发

- 原始现象：中键+后侧键切换回报率、中键+前侧键切换 DPI 时，前/后侧键也会触发。
- 可能根因：组合键识别发生在普通按键事件发布之后，缺少 chord 消费机制。
- 修改方案：增加 chord arbiter；在组合判定窗口内暂存组成键，组合成立后消费其
  press/release，仅发布设置变化；组合失败才按原顺序补发普通按键。
- 验收：两个组合各执行 1,000 次，设置每次只变化一档，host 端侧键事件为 0。

### T-05 [high] 光微动 8K 不稳定，2.4G 实测约 7600 Hz

- 原始现象：光微动模式有线 8000 Hz 不稳定；2.4G 8000 Hz 实测约 7600 Hz。
- 可能根因：光微动扫描与 report scheduler 抢占；RF 时隙、重试和包聚合预算不足；
  时钟源或定时周期存在系统性偏差。
- 修改方案：以硬件定时器驱动采样/发送；建立每 125 µs CPU、SPI、RF 时间预算；
  将重试移出下一个实时 deadline；输出 missed-deadline 计数。
- 验收：按统一测试工具和负载条件，持续 30 分钟达到 8K 规格定义的容差，
  无周期性抖动或输入失效。

### T-06 [high] 有线磁微动 4K/8K 实测仅约 2700 Hz

- 原始现象：有线磁微动模式配置 4000/8000 Hz 时，实测只有约 2700 Hz。
- 可能根因：磁/HE ADC 扫描周期约束 report loop；扫描、滤波和 USB 上报串行执行。
- 修改方案：ADC 扫描、触发算法与 USB IN pipeline 化；缓存最新稳定按键状态，
  不让 ADC 转换阻塞每个 USB microframe；分析 ISR 优先级与执行时间上界。
- 验收：磁微动模式 4K/8K 在运动、双键和滚轮并发下达到各自规格容差。

### T-07 [high] 2.4G 充电时 4K/8K 实测仅约 2600 Hz

- 原始现象：2.4G 模式接入充电器后，4000/8000 Hz 实测约 2600 Hz。
- 可能根因：VBUS/充电事件错误切换到限频电源 profile；充电管理中断过密；
  USB 插入状态误改变无线 scheduler 或系统时钟。
- 修改方案：把“USB 供电/充电”和“有线数据模式”分开建模；保持用户选择的
  2.4G 高性能时钟；降低充电遥测频率并限制中断执行时间。
- 验收：2.4G 4K/8K 在未充电、充电和满充保持三种状态均达到规格容差。

### T-11 [high] 2.4G 回连约 10 秒，规格为 3 秒

- 原始现象：2.4G 回连时间实测约 10 秒；规格为 3 秒。
- 可能根因：扫描窗口、退避或频道遍历参数错误；配对表加载异常；先进入完整配对
  流程而非快速回连。
- 修改方案：为已绑定接收器增加 fast reconnect 路径；优先最近频道/接入码；
  将扫描、退避和超时参数集中到版本化配置。
- 验收：标准 RF 环境下执行 200 次回连，每次不超过 3 秒，并报告 P50/P95/P99。

### T-13 [high] 鼠标重置后未清除 2.4G 配对信息

- 原始现象：鼠标重置成功后，2.4G 配对信息仍保留。
- 已有关联证据：二进制审计确认启动时加载
  `ppt_ptx/bond/(null)`，但注册的 settings handler 根为 `ppt_ptx/bond`。
- 可能根因：恢复出厂只清运行态或清错 settings 子树；擦除后未同步/提交。
- 修改方案：定义 factory reset 的完整键空间；枚举并删除所有 2.4G/BLE bond、
  receiver slot 和缓存；同步持久化存储后再报告成功。
- 验收：重置后旧接收器无法直接回连；断电重启后仍为空；重新配对后功能正常。

### T-16 [high] 双接收器配对后的回连选择失败

- 原始现象：两个接收器分别配对成功后，分别拔掉不同 dongle，不能回连成功。
- 可能根因：bond slot 被覆盖；当前 receiver ID 与实际在线 receiver 未匹配；
  配对表加载错误与 B-03 的空子树问题相关。
- 修改方案：使用稳定 receiver ID 索引 bond；配对写入原子化；连接时遍历有效
  receiver slots，而不是只读取 last-active 指针；修复 settings 根路径。
- 验收：双接收器在全部插拔顺序、断电和模式切换组合中完成回连，并连接到预期槽位。

### T-20 [high] 待机功耗约 3.2 mA

- 原始现象：待机功耗约 3.2 mA；详细测量数据位于测试表格 2。
- 可能根因：PAW/ADC/RF/高频时钟或 LED 域未关闭；错误 wake source 造成频繁唤醒；
  未真正进入目标低功耗状态。
- 修改方案：增加按电源域统计的 sleep trace；休眠前关闭 PAW、ADC、RF、USB
  非必要时钟与 LED；用 GPIO/RTC 唤醒；统计 sleep residency 和 wake reason。
- 验收：按“表格 2”相同仪器、固件设置和时间窗口复测，平均/峰值功耗均满足批准规格。

## P2/P3：一致性与体验问题

### T-01 [medium] 有线与蓝牙版本号不一致

- 原始现象：有线显示 `1.0.0`，蓝牙显示 `0.1.0`。
- 影响：升级器、Launcher、客服和测试无法可靠判断运行版本。
- 可能根因：USB 与 BLE Device Information Service 使用不同常量，或 BLE
  仍保留早期默认版本。
- 修改方案：由构建系统生成唯一版本源，同时填充 MCUboot header、USB/Launcher
  查询和 BLE DIS；CI 比较所有导出版本。
- 验收：有线、2.4G、BLE、升级器和镜像元数据均返回批准的同一版本语义。

### T-10 [medium] 2.4G 对码请求周期约 2 秒，规格为 1 秒

- 原始现象：无线模式对码频率实测 2 秒/次，规格为 1 秒/次。
- 可能根因：定时单位或重复计时错误；一次请求后额外等待了一个周期。
- 修改方案：用单调定时器按绝对 deadline 调度请求，避免“任务耗时 + delay”
  累加；统一规格常量。
- 验收：连续 100 次对码广播的相邻间隔为 `1.0 s`，误差落在批准容差内。

### T-14 [medium] 快速切换 2.4G/BLE 时灯效异常

- 原始现象：快速拨动 2.4G 与蓝牙模式时灯光异常。
- 可能根因：多个异步模式任务同时拥有 LED；旧模式定时器在新模式继续回调。
- 修改方案：LED 由单一状态机管理；模式切换使用 generation token 取消旧动画；
  新模式入口先清除 pending timer/work。
- 验收：以不同间隔快速切换 500 轮，灯效始终与最终连接状态一致。

### T-15 [low] 切到蓝牙模式时灯光亮起慢

- 原始现象：拨动开关到蓝牙模式后，灯光亮起慢。
- 可能根因：LED 反馈等待 BLE 栈初始化或扫描完成。
- 修改方案：将“已检测到物理模式切换”的即时反馈与“连接状态”动画分离。
- 验收：拨动开关后在批准的人机反馈时间内点亮，后续正确切换到配对/回连状态灯效。

## 共同修复工作包

### WP-1：输入事件原子性

覆盖：T-02、T-03、T-08、T-09。

- chord 消费；
- neutral report；
- 模式切换清队列；
- session epoch；
- report 零初始化；
- press/release 不依赖 motion。

### WP-2：高回报率实时调度

覆盖：T-04、T-05、T-06、T-07、T-17。

- 光/磁扫描与 USB/RF 发送解耦；
- 定时器、ISR 和任务优先级预算；
- ring buffer、deadline 与丢包遥测；
- 充电状态不得隐式改变用户回报率；
- 异常降频自动恢复和原因保留。

### WP-3：无线连接与持久化

覆盖：T-10、T-11、T-12、T-13、T-16。

- 1 秒对码 deadline；
- 3 秒 fast reconnect；
- 所有休眠失败路径保持 wake source；
- 修复 `ppt_ptx/bond` 根路径；
- 多 receiver slot 原子持久化与选择。

### WP-4：电源可靠性

覆盖：T-18、T-19、T-20。

- 电池/VBUS 启动仲裁；
- UVLO/brownout 阈值与启动时序；
- 无电池 USB 独立供电；
- PAW/RF/ADC/LED/时钟休眠门控；
- reset/wake reason 与功耗 trace。

### WP-5：版本和灯效

覆盖：T-01、T-14、T-15。

- 单一构建版本源；
- 单一 LED 状态机；
- 取消旧模式异步任务；
- 即时物理模式反馈。

## 测试资料缺口

- “表格 2”待机功耗原始数据尚未放入当前工作区；
- 每项测试的样本数、主机配置、测试软件、固件配置和 RF 环境尚未附带；
- 7600/2700/2600/24 Hz 的采样窗口和统计方法尚未附带；
- 双接收器的预期选路规则需写入正式规格。

这些缺口不否定已报告现象，但必须补齐后才能建立可重复的自动化回归基线。
