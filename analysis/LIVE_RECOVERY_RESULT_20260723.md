# G6 HE 现场恢复结果

日期：2026-07-23  
设备：Keychron G6 HE `3434:D086`  
固件：`1.0.0+5`  
连接：鼠标有线，接收器已拔除

## 已完成

- 唯一目标已确认：一只 G6 HE、四个 HID 接口、无序列号；
- 原厂配置协议已确认：
  - `B3` 63 字节长命令；
  - `B4` 63 字节长响应；
  - `B5` 20 字节短命令；
  - `B6` 20 字节短响应；
- 只读命令 `0x02/0x04/0x06/0x49/0x4B/0x65` 均正常响应；
- 原厂恢复全部 `B5/0x0F/0xFF` 返回 `E4 00 0F`，配置确实恢复；
- 更新接口 system reset `0x66` 成功触发 USB 离线和重新枚举；
- v6 DPI `0x48/0x49` 已回读验证：
  - X/Y 均为 `400/800/1600/3200/5000`；
  - 当前档为 2；
- v6 双模式 polling `0x4A/0x4B` 已回读验证：
  - 当前有线模式为 level 5，即 8000 Hz；
- sensor 20K `0x42/0x06` 已回读验证为开启；
- 私有 WebHID 页面已归档至 Kunkka 项目记录：
  - <https://github.com/SvenKunkka/g6-he-development-workspace>
  - 支持 DPI、125–8000 Hz、20K、五个主按键映射和原厂配置恢复。

## 仍未恢复

三次各 12 秒的普通鼠标 interface-0 抓取均收到 `0` 个报告。配置恢复、MCU reset、
重新应用 20K 和 8K 后结果不变。

HE 只读状态显示左右键：

- `adc_flag=1`；
- ADC 均为 `0/0`；
- trigger mode 为 1；
- RT 未开启。

因此现场故障不是 USB 枚举失败，也不是 DPI/回报率配置损坏。当前证据指向以下范围：

1. 光磁/HE 扫描路径未产生有效采样；
2. PAW 传感器或其 SPI 初始化失败后拖住输入线程；
3. 输入事件线程、队列或中断路径永久停滞；
4. 板级供电、模式检测脚或传感器信号异常。

## 为什么没有直接刷写

鼠标 update HID 没有 flash readback，当前无法取得完整原厂 flash、settings 和 bootloader
备份；官方产品记录同时标记 `support_update=0`，发布 API 没有该固件版本。现有镜像虽然
签名有效，但与运行版本相同，重刷不能证明能解决线程/硬件故障，而且一旦更新中断没有
已验证 USB 恢复链路。

DIY 固件已经构建为 nRF54LM20A 独立 SWD 镜像，但它不是原厂签名升级包。直接装入需要
SWD 探针、可读目标、完整备份和恢复验证；当前电脑没有检测到这些条件，因此没有对 flash
执行写入或擦除。

## 下一硬件动作

最小可控路径是接入 J-Link/CMSIS-DAP：

1. 识别并唯一锁定 nRF54LM20A；
2. 读取 UICR、bootloader、应用、settings 和全 flash；
3. 校验备份可重复读取；
4. 先验证 halt/reset/recover；
5. 再决定重刷原厂签名镜像或烧录 DIY SWD 镜像。
